# Review checklist

Use this checklist when reviewing PRs generated by humans or agents.

## Product fit

- [ ] The change supports the current roadmap.
- [ ] The change does not overbuild beyond the issue scope.
- [ ] The v0.1 structured data to Neo4j loop remains simple.
- [ ] New abstractions have a clear near-term use case.

## Architecture

- [ ] Core logic is in `packages/graphflow_core` where appropriate.
- [ ] CLI/API/worker layers are thin wrappers.
- [ ] Interfaces are introduced only where useful.
- [ ] No unnecessary platform dependency was introduced.
- [ ] The design remains compatible with future CLI/API/MCP/Dagster/Temporal adapters.

## Manifests

- [ ] Manifest shape is declarative and predictable.
- [ ] Pydantic validation is used for manifest models.
- [ ] References across manifests are validated.
- [ ] Secrets are referenced via environment variables, not stored directly.
- [ ] Docs/examples are updated for manifest changes.

## Graph behaviour

- [ ] Node writes are idempotent.
- [ ] Relationship writes are idempotent where possible.
- [ ] Required properties are validated before load.
- [ ] Duplicate node keys are detected or handled.
- [ ] Orphan relationships are detected or handled.
- [ ] Neo4j-specific logic is isolated behind the graph sink boundary.

## Extraction and entity resolution

- [ ] Fast extraction remains the cheap/default path.
- [ ] LLM extraction is optional, cached, and cost-limited.
- [ ] Ambiguous entity-resolution decisions can be reviewed or deferred.
- [ ] External reference lookups are optional and cached where possible.

## Testing

- [ ] Tests cover the main core behaviour changed.
- [ ] Tests do not require paid API keys.
- [ ] Integration tests are clearly marked if they require Docker services.
- [ ] Error cases are tested where practical.

## Documentation

- [ ] README or docs are updated if user-facing behaviour changed.
- [ ] Architecture docs are updated if module boundaries changed.
- [ ] Manifest docs are updated if config shape changed.
- [ ] Roadmap is updated if scope changes.

## Security and cost

- [ ] No real secrets or credentials are committed.
- [ ] No unnecessary external network calls are added.
- [ ] No always-on cloud dependency is introduced for local development.
- [ ] Paid APIs are not required for the v0.1 happy path.
